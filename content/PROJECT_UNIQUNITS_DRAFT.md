# Project Draft
## UniqUnits

### Summary
Мобильное приложение для работы с авторским индикатором, который помогает трейдерам входить в сделку при совпадении определенных факторов. Проект был про плотный интерфейс, быстрые действия и удобную работу с важной информацией на мобильном экране.

### Problem
Нужно было сделать плотный трейдинговый интерфейс управляемым на мобильном устройстве и при этом не потерять скорость доступа к ключевым данным, инструментам и сценариям.

### Tasks
- анализ конкурентов;
- интервью с трейдерами;
- выдвижение и проверка гипотез;
- прототипирование;
- дизайн интерфейса;
- проектирование состояний экранов;
- проработка мобильного UX для плотного продукта.

### Results
- собрал мобильную структуру для плотного трейдингового интерфейса;
- упростил доступ к важной информации и ресурсам;
- спроектировал состояния экранов для ключевых сценариев;
- адаптировал управление под быстрые действия рукой;
- снизил когнитивную нагрузку в сценариях алго-ордеров и отслеживания инструментов.

### Modules

#### Контекст
Компания обратилась с запросом разработать приложение для работы с авторским индикатором для трейдеров. Помимо общего удобства нужно было решить проблему плотности интерфейса и упростить доступ к критичным действиям.

#### Исследование
- провел предпроектную аналитику;
- выдвинул гипотезы и часть скорректировал по ходу работы;
- провел интервью с опытными трейдерами;
- детально изучил ожидания и реальные привычки аудитории.

#### Главный экран и трейд-лист
- спроектировал главный экран как список отслеживаемых валютных пар;
- предусмотрел стартовый набор популярных инструментов при первом входе;
- заложил сценарий быстрой кастомизации списка.

#### Алго-ордеры
- сделал отдельный сценарий для быстрого применения шаблонов;
- упростил настройку ордеров в условиях рыночной нестабильности;
- расположил управление ближе к нижней части экрана для удобства одной рукой.

#### Состояния и вспомогательные сценарии
- спроектировал skeleton, placeholder, loading, error, success;
- добавил подсказки для сложных настроек;
- снизил необходимость уходить в отдельные статьи и туториалы.

### Итог
Этот кейс был для меня важен как пример плотного мобильного продукта, где нужно было думать не только о визуале, но и о скорости принятия решений в интерфейсе.

### Чему я научился
- работать с перегруженными мобильными сценариями;
- проектировать интерфейс под скорость действия, а не только под чтение;
- учитывать реальные привычки профессиональных пользователей.
