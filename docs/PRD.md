# PRD
## Portfolio Website

### 1. Документ
- Версия: `v1`
- Язык интерфейса: `RU`
- Статус: `Draft / approved for MVP planning`
- Владелец: `Yerik`

### 2. Контекст
Нужно собрать новое портфолио продуктового дизайнера с фокусом на наиболее сильный и свежий опыт. Текущая задача не в том, чтобы сразу отполировать тексты до финальной редакции, а в том, чтобы:
- собрать правильную иерархию страниц;
- разложить контент по понятным уровням;
- выделить главный кейс и вторичные проекты;
- заложить минимальную, но строгую визуальную систему;
- подготовить основу для последующей реализации и полировки.

Главный приоритет в портфолио — показать опыт в `Mechta.kz`. Вторичный уровень — архивный опыт: фриланс, агентство, другие работы.

### 3. Продуктовая цель
Создать спокойный, текстоцентричный и убедительный сайт-портфолио, который:
- быстро объясняет, кто автор и чем занимается;
- выводит сильнейшие проекты на первый план;
- позволяет читать кейсы как короткие статьи;
- не перегружен декоративностью;
- легко расширяется новыми проектами и разделами без пересборки архитектуры.

### 4. Product statement
Это не “витрина красивых картинок”, а редакторски собранное портфолио с акцентом на содержательность, логику и читаемость.

### 5. Scope v1
#### Входит
- Главная страница.
- Полноценный проект `Редизайн e-commerce`.
- Полноценный проект `Partners`.
- Превью `Ценники`.
- Превью `Корпоративный портал`.
- Архивный блок `Фриланс`.
- Архивный блок `BMC Group / маркетинговое агентство`.
- CTA-секция с контактами.
- Базовая система компонентов и типографики.

#### Не входит
- Полная редактура всех текстов.
- Английская версия.
- CMS.
- Блог.
- Полноценные страницы под `Ценники` и `Корпоративный портал` в `v1`.
- Полноценные отдельные страницы под архивный фриланс и агентский опыт.

### 6. Информационная архитектура
Иерархия:
1. `Главная`
2. `Проект`

Компании в этой модели не являются отдельными страницами. Они существуют как визуальные и контентные секции на главной странице.

Основной поток:
`/` -> секция `Mechta.kz` -> `/projects/ecommerce-redesign` или `/projects/partners`

Дополнительный поток:
`/` -> архивные секции `Фриланс`, `BMC Group` -> без углубления или с пометкой `Скоро`

### 7. Карта сайта
- `/`
- `/projects/ecommerce-redesign`
- `/projects/partners`

Потенциальные будущие маршруты:
- `/projects/pricing-labels`
- `/projects/corporate-portal`

### 8. Структура главной страницы
#### 8.1 Fixed top nav
Содержит только текстовые ссылки:
- `Обо мне`
- `Mechta.kz`
- `Проекты`
- `Опыт`
- `Контакты`

#### 8.2 Hero / summary
Содержит:
- имя;
- роль;
- короткий summary;
- ссылки: `Telegram`, `LinkedIn`, `Email`, `Resume`.

#### 8.3 Company sections
Главная страница состоит из последовательных секций по компаниям.

Порядок секций:
1. `Mechta.kz`
2. `Фриланс`
3. `BMC Group / маркетинговое агентство`

Для каждой секции:
- название компании;
- период;
- короткий контекст;
- список проектов или архивных карточек.

`Mechta.kz` должна быть главным фокусом страницы.

#### 8.4 Resume block
Короткий блок-подсуммирование:
- сколько лет опыта;
- основные типы проектов;
- где работал;
- чем силен.

#### 8.5 CTA
Финальный крупный блок со связью.

### 9. Структура секции компании на главной
Отдельная страница компании в `v1` не используется. Вместо нее на главной есть обзорная секция компании.

Секция `Mechta.kz` должна содержать:
- название компании;
- 1-3 абзаца о компании, роли и контексте;
- meta-информацию: роль, период, формат;
- список проектов внутри компании.

Что должно быть объяснено в секции:
- `Mechta.kz` - один из крупнейших ритейлеров Казахстана;
- роль - продуктовый дизайнер;
- период и формат работы;
- зона ответственности - B2C, конверсия, клиентский путь, дизайн-система, взаимодействие с большим числом команд;
- ограничения среды - архитектура, сложные процессы, согласования.

Список проектов:
- `Редизайн e-commerce` - clickable;
- `Partners` - clickable;
- `Ценники` - preview only;
- `Корпоративный портал` - preview only.

### 10. Структура страницы проекта
Для всех полноценных проектных страниц используется единый шаблон.

Содержит:
- fixed top nav;
- hero visual;
- meta-блок;
- 2-3 вводных абзаца;
- блок `Что получилось`;
- блок `Что я делал`;
- блок `Контекст и проблема`;
- блок `Подход / процесс`;
- блок `Ключевые решения`;
- галерею;
- перелинковку на соседний проект;
- возврат на главную секцию `Mechta.kz`.

### 12. Первичное наполнение
#### 12.1 Mechta.kz
- один из крупнейших ритейлеров в Казахстане;
- 50+ магазинов;
- `MAU 500k`;
- фокус на повышении конверсии и улучшении B2C UX;
- роль: продуктовый дизайнер;
- обязанности: редизайн страниц, итеративные улучшения, исследование, концепты, развитие дизайн-системы, документация, дизайн-ревью, генерация с AI, прототипирование, тепловые карты, запись экранов.

#### 12.2 Редизайн e-commerce
Включает:
- страница товара;
- корзина;
- оформление заказа;
- детали заказа;
- мои заказы;
- гарантийные услуги как встроенный мини-проект.

#### 12.3 Partners
Отдельный внутренний проект про обработку предложений поставщиков и партнеров, отказ от ограничений `1С`, борьбу с дублями и ускорение операционного процесса.

### 13. Правила работы с текстом
На первом этапе тексты раскладываются по смысловым блокам без финальной редакторской чистки.

Обязательные правила:
- длинные полотна резать на абзацы;
- где есть перечни, использовать bullets;
- где есть последовательность, использовать нумерацию;
- не тянуть текст на всю ширину контейнера;
- различать “что получилось” и “что делал”.

### 14. Визуальная система
- фон: белый;
- цвета: черный, серый `50% black`, белый;
- шрифт: `IBM Plex Serif`;
- размеры:
  - `16px` — body, nav, meta;
  - `24px` — section title;
  - `48px` — display title;
- весь сайт живет в центральной колонке примерно `720px`;
- компании на главной отделяются текстом и ритмом, а не отдельными landing pages.

### 15. Критерии готовности MVP
MVP считается собранным, если:
- есть главная;
- на главной есть сильная секция `Mechta.kz`;
- есть кейс `Редизайн e-commerce`;
- есть кейс `Partners`;
- есть превью для вторичных проектов;
- есть архивный блок;
- есть навигация между главной и проектами;
- есть CTA и контакты.
