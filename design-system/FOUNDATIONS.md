# Foundations

## 1. Визуальная идея
Сайт должен быть похож на короткое печатное портфолио или аккуратно сверстанную статью, а не на типовой продуктовый лендинг.

Опорные принципы:
- максимум внимания контенту;
- минимум визуального шума;
- четкая иерархия;
- спокойный ритм;
- много воздуха;
- повторяемые паттерны.

## 2. Цвета
- `--color-bg: #FFFFFF`
- `--color-text: #000000`
- `--color-text-muted: rgba(0, 0, 0, 0.5)`
- `--color-border-subtle: rgba(0, 0, 0, 0.12)`

## 3. Типографика
- Font family: `IBM Plex Serif`

Размеры:
- `16px` - body, nav, meta, links
- `24px` - section title
- `48px` - page title / case title

Роли:
- `text-body`
- `text-section`
- `text-display`

## 4. Layout tokens
- Узкая колонка текста для читаемых секций.
- Широкая медиа-зона для обложек и галереи.
- Sticky header.
- Большие вертикальные интервалы между смысловыми блоками.

## 5. Reusable components

### TopNav
Используется на всех страницах.

### HeroSummary
Имя, роль, intro, ссылки.

### CompanyCard
Карточка компании на главной.

### ProjectCard
Карточка проекта внутри компании.

### PreviewCard
Некликабельный или полуактивный блок для будущих кейсов.

### MetaList
Короткие facts:
- роль
- период
- формат
- статус

### RichTextSection
Универсальный блок для длинного текста и абзацев.

### MetricsList
Список коротких достижений.

### TasksList
Список того, что делал автор.

### ImageGallery
Вертикальный стек изображений.

### ProjectPager
Навигация на следующий/предыдущий проект.

### CTASection
Финальный блок со связью.

## 6. Правила ссылок
- Все ссылки текстовые.
- Hover только через underline.
- Без тяжелых кнопочных паттернов, если это не CTA.

## 7. Правила текста
- Не ставить слишком длинные строки.
- Разбивать большой текст на абзацы.
- Там, где нужен перечень, делать bullets.
- Там, где нужен процесс, делать numbering.

## 8. Правила изображений
- Обложка проекта крупная и заметная.
- Скриншоты идут вертикальным потоком.
- Изображения могут быть шире текстовой колонки.
- Если изображения пока нет, допускается placeholder.

## 9. Стандарты для MVP
- сначала консистентность;
- потом декоративность;
- сначала reuse;
- потом уникальные исключения.
